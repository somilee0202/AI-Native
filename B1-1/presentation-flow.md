# 발표 및 평가 흐름

## 1. 전체 발표 전략

발표는 `요구사항 확인 -> 입력 데이터 -> 모델 비교 -> 시스템 설계 -> 실행 검증` 순서로 진행한다.

핵심 메시지는 다음과 같다.

```txt
저는 실제 스타트업 회의록 요약 자동화를 과업으로 선택했고,
3개 모델을 동일 조건에서 비교한 뒤 Claude를 최종 모델로 선정했습니다.
이후 Claude 기준으로 시스템 프롬프트, Few-shot, 환각 검증, 10턴 대화 로그까지 구성했습니다.
```

## 2. 추천 발표 순서

### 1. `mission.md`

**목적:** 과제 요구사항을 먼저 짚는다.

**설명 포인트:**

```txt
이번 과제는 업무 자동화 프롬프트 패키지를 만드는 것이고,
필수 산출물은 모델 비교 보고서, 시스템 설계 문서, 실행 로그 3가지입니다.
저는 실제 스타트업 회의록 요약 자동화를 과업으로 선택했습니다.
```

### 2. `final-checklist.md`

**목적:** 미션 요구사항 충족 여부를 한눈에 보여준다.

**설명 포인트:**

```txt
mission.md 기준으로 요구사항을 항목별로 다시 체크했습니다.
3개 모델 비교, Few-shot, v1->v2 개선, 환각 검증, 10턴 로그까지 모두 Pass 상태입니다.
제출 전 개인정보와 내부 정보도 익명화했습니다.
```

### 3. `0623 익명 스타트업 회의.txt`

**목적:** 실제 입력 데이터가 무엇인지 보여준다.

**설명 포인트:**

```txt
모델 비교와 10턴 대화에 사용한 실제 회의 녹취록입니다.
공개 제출을 위해 서비스명, 사용자명, 외부 도구명, 내부 수치를 익명화했습니다.
긴 회의록이기 때문에 모델의 문맥 처리와 요약 품질을 비교하기 적합했습니다.
```

### 4. `model-test-prompt.md`

**목적:** 모델 비교의 동일 조건을 보여준다.

**설명 포인트:**

```txt
ChatGPT, Claude, Gemini에 같은 파일과 같은 프롬프트를 넣었습니다.
원문에 없는 담당자, 마감일, 예산, 정책, 수치를 만들지 말라는 규칙을 넣었습니다.
모델별 응답 원문도 이 파일에 보관했습니다.
```

### 5. `model-comparison-report.md`

**목적:** 핵심 산출물 1번인 모델 비교 결과를 설명한다.

**설명 포인트:**

```txt
3개 모델을 정확성, 형식 준수, 한국어 자연스러움, 문맥 유지, 모호성 대응 5개 축으로 평가했습니다.
Claude가 23점으로 가장 높았고, 최종 모델로 선정했습니다.
선정 이유는 불명확한 정보와 담당자 미정 항목을 가장 안정적으로 처리했기 때문입니다.
```

**특히 보여줄 부분:**

```txt
3. 비교 대상 모델 및 사용 환경
6. 점수표
7. 최종 선정 결론
```

### 6. `system-design.md`

**목적:** 핵심 산출물 2번인 시스템 설계를 설명한다.

**설명 포인트:**

```txt
최종 선정 모델인 Claude 기준으로 회의록 정리 봇을 설계했습니다.
페르소나는 스타트업 회의록 정리 전문 AI 어시스턴트 '민서'로 정의했습니다.
시스템 프롬프트에는 역할, 출력 형식, 안전장치, 사실/수치 처리 규칙을 포함했습니다.
```

**특히 보여줄 부분:**

```txt
7. 페르소나
9. 최종 시스템 프롬프트
10. Few-shot 예시
11. v1 -> v2 개선 이력
12. 환각 검증 설계
```

### 7. `claude-10turn-script.md`

**목적:** 10턴 대화 실행 과정을 보여준다.

**설명 포인트:**

```txt
최종 선정 모델인 Claude로 10턴 대화를 진행하기 위한 스크립트입니다.
중간에 팀 내부 공유용에서 대표/임원 보고용으로 조건을 변경했습니다.
뒤늦게 담당자 정보를 추가 제공해 모델이 문맥을 유지하는지 확인했습니다.
```

### 8. `raw-conversation-log.md`

**목적:** 원본 로그 전문을 보관했다는 점을 보여준다.

**설명 포인트:**

```txt
미션에서 원본 로그를 별도 파일로 남기라고 했기 때문에 10턴 전체 대화를 보관했습니다.
재현 가능성을 위해 User 1~10과 Claude 응답 1~10을 그대로 남겼습니다.
```

### 9. `conversation-log.md`

**목적:** 핵심 산출물 3번인 실행 로그 정리본을 설명한다.

**설명 포인트:**

```txt
raw log를 그대로 제출하지 않고, 평가하기 쉽게 시나리오, 대화 흐름, 문제 지점, 문맥 유지 평가로 정리했습니다.
Claude가 대부분 문맥을 유지했지만, 초기 응답에서 담당자를 추정한 문제가 있었고 이후 추가 정보 반영 과정에서 정정했습니다.
최종적으로 10턴 대화, 조건 변경, 추가 정보 제공, 문맥 유지 검증을 모두 충족했습니다.
```

**특히 보여줄 부분:**

```txt
2. 대화 흐름 요약
3. 필수 상황 포함 여부
4. 문제 발생 지점과 수정 결과
5. 문맥 유지 평가
```

## 3. 짧은 발표용 순서

시간이 짧다면 아래 5개 파일만 보여준다.

```txt
final-checklist.md
-> model-comparison-report.md
-> system-design.md
-> conversation-log.md
-> raw-conversation-log.md
```

## 4. 한 문장 요약

```txt
실제 스타트업 회의록을 대상으로 3개 LLM을 비교했고, 가장 안정적으로 불확실성을 처리한 Claude를 선택해 회의록 요약 봇의 프롬프트 패키지와 10턴 검증 로그를 완성했습니다.
```
