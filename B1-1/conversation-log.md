# 실행 로그

## 1. 시나리오 설명

- 선택 모델: Claude
- 사용 환경: 웹
- 사용 날짜: 2026-06-26
- 첨부 파일: `0623 익명 스타트업 회의.txt`
- 과업: 실제 스타트업 회의 녹취록을 회의록으로 정리하고, 조건 변경과 추가 정보를 반영해 최종 보고용 문서로 다듬기
- 원본 대화 전문: `raw-conversation-log.md`

이번 실행 로그는 최종 선정 모델인 Claude가 긴 회의 녹취록의 문맥을 유지하면서 결정사항, Action Items, 리스크, 후속 일정, 확인 필요 사항을 분리할 수 있는지 검증하기 위해 작성했다.

## 6. 최종 평가

Claude는 긴 스타트업 회의 녹취록을 기반으로 10턴 동안 문맥을 대체로 안정적으로 유지했다. 중간에 보고 대상이 바뀌었을 때 문체와 구조를 조정했고, 뒤늦게 제공한 담당자 정보도 기존 제약을 깨지 않고 반영했다.

가장 중요한 개선 지점은 원문에 없는 담당자 추정을 처음부터 하지 않도록 프롬프트에서 더 강하게 제한하는 것이다. 최종 프롬프트에는 `추정 담당자도 쓰지 말고, 명시되지 않으면 반드시 미정 또는 확인 필요로 표시한다`는 규칙을 추가하는 것이 적절하다.
