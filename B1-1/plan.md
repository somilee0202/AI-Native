# 미션 수행 계획

## 1. 미션 요약

이번 미션의 목표는 ChatGPT를 포함한 LLM을 업무 자동화에 제대로 활용하기 위한 프롬프트 패키지를 완성하는 것이다.

최종 제출물은 다음 3가지다.

1. LLM 모델 비교·선정 보고서
2. 시스템 설계 문서
3. 10턴 이상 실행 로그

## 2. 추천 업무 과업

추천 과업은 **회의록 요약 자동화**다.

회의 메모나 녹취 요약 텍스트를 입력하면 다음 항목으로 정리하는 봇을 설계한다.

- 결정사항
- Action Items
- 리스크
- 후속 일정
- 확인 필요 사항

이 과업을 추천하는 이유는 다음과 같다.

- 모델별 결과 품질을 비교하기 쉽다.
- 10턴 이상 대화 시나리오를 자연스럽게 만들 수 있다.
- 환각 검증 기준을 명확하게 세울 수 있다.
- 실제 업무에서 재사용 가능성이 높다.

## 3. 제출 파일 구성

다음 파일 구조로 작성한다.

```txt
B1-1/
  mission.md
  plan.md
  model-comparison-report.md
  system-design.md
  conversation-log.md
  raw-conversation-log.md
```

각 파일의 역할은 다음과 같다.

- `model-comparison-report.md`: 3개 이상 LLM의 결과 비교와 최종 선정 근거
- `system-design.md`: 문제 정의, 페르소나, 시스템 프롬프트, Few-shot, 환각 검증, 개선 이력
- `conversation-log.md`: 가독성 있게 정리한 10턴 이상 실행 로그
- `raw-conversation-log.md`: 원본 대화 전문

## 4. 단계별 수행 계획

### 1단계: 업무 과업 정의

회의록 요약 과업을 기준으로 다음 항목을 정의한다.

- 타겟 사용자: 팀 리더, PM, 기획자 등
- 입력 데이터 형태: 회의 메모, 녹취 요약, 채팅 기록
- 출력 규격: 결정사항 / Action Items / 리스크 / 후속 일정 / 확인 필요 사항
- 재사용 가능한 입력 템플릿

입력 템플릿 예시:

```txt
[회의 목적]
[참석자]
[회의 원문 또는 메모]
[원하는 결과]
[톤]
[필수 포함 항목]
[금지 사항]
```

### 2단계: 비교할 LLM 3종 선정

최소 3개 모델을 선정해 동일한 입력으로 테스트한다.

예시 모델:

- ChatGPT 계열 모델
- Claude 계열 모델
- Gemini 계열 모델

모델별로 반드시 기록할 항목:

- 모델명
- 사용 환경: 웹/앱/API
- 요금제: 무료/유료
- 사용 날짜
- 주요 설정: temperature, top_p, max_tokens 등 확인 가능한 항목
- 무료 버전 사용 시 제한점

### 3단계: 모델 비교 기준 설계

평가 축은 최소 4개 이상 필요하다. 다음 5개 축을 사용한다.

| 평가 축 | 설명 |
| --- | --- |
| 정확성 | 원문에 없는 내용을 만들지 않는가 |
| 형식 준수 | 지정한 출력 포맷을 지키는가 |
| 한국어 자연스러움 | 업무 문서로 바로 사용할 수 있는가 |
| 문맥 유지 | 조건 변경 후에도 앞선 요구사항을 유지하는가 |
| 모호성 대응 | 불명확한 부분을 질문하거나 확인 필요로 표시하는가 |

각 항목은 1~5점으로 평가하고, 점수마다 짧은 근거를 남긴다.

### 4단계: 모델 비교·선정 보고서 작성

`model-comparison-report.md`는 다음 목차로 작성한다.

```md
# 모델 비교·선정 보고서

## 1. 비교 목적
## 2. 비교에 사용한 동일 입력
## 3. 비교 대상 모델 및 사용 환경
## 4. 평가 기준
## 5. 모델별 결과 요약
## 6. 점수표
## 7. 최종 선정 결론
```

최종 선정 결론에는 선택한 모델이 해당 업무 과업에 적합한 이유를 3줄 이상 작성한다.

### 5단계: 페르소나 및 시스템 프롬프트 설계

회의록 요약 봇의 페르소나를 구체적으로 정의한다.

예시:

- 이름: 민서
- 역할: 사내 회의록 정리 전문 어시스턴트
- 전문 분야: 회의 요약, 결정사항 추출, Action Items 정리
- 말투: 간결하고 실무적인 한국어
- 우선순위: 정확성 > 누락 방지 > 간결함
- 금지 사항: 원문에 없는 결정사항 생성 금지, 담당자 임의 지정 금지

시스템 프롬프트에는 다음 요소를 포함한다.

- 역할과 목표
- 출력 형식 규칙
- 안전장치: 모르면 모른다고 말하기, 확인 질문하기
- 사실/정책/수치 처리 규칙
- 최종 답변에 장문의 추론 과정을 노출하지 않는 규칙

### 6단계: Few-shot 예시 3개 작성

동일 과업에 대해 좋은 입력과 좋은 출력 예시를 최소 3개 작성한다.

구성:

1. 정상적인 회의 메모
2. 담당자와 마감일이 포함된 회의 메모
3. 모호한 회의 메모

세 번째 예시는 AI가 바로 단정하지 않고 확인 질문 또는 확인 필요 항목을 제시하도록 설계한다.

### 7단계: v1과 v2 프롬프트 비교

같은 입력에 대해 두 버전을 비교한다.

v1 예시:

```txt
아래 회의록을 요약해줘.
```

v2 예시:

```txt
아래 회의록을 결정사항, Action Items, 리스크, 후속 일정, 확인 필요 사항으로 나누어 정리해줘.
원문에 없는 내용은 만들지 말고, 불명확한 내용은 확인 필요로 표시해줘.
내부적으로는 단계적으로 검토하되, 최종 답변에는 핵심 근거만 간단히 제시해줘.
```

비교할 항목:

- 출력 구조가 명확해졌는가
- 원문에 없는 내용을 만들지 않았는가
- 불명확한 정보가 확인 필요로 표시되었는가
- 업무 문서로 바로 사용할 수 있는가

### 8단계: 환각 검증 질문 5개 설계

환각은 사실, 수치, 정책, 계산처럼 검증 가능한 내용에서 근거 없이 틀린 정보를 확신하는 답변으로 정의한다.

검증 질문 예시:

| 번호 | 검증 항목 | 기대 동작 |
| --- | --- | --- |
| 1 | 원문에 없는 담당자를 묻기 | 임의로 만들지 않고 확인 필요 표시 |
| 2 | 확정되지 않은 일정을 묻기 | 확정 여부를 구분 |
| 3 | 예산 수치를 묻기 | 원문에 없으면 없다고 답변 |
| 4 | 모호한 약어를 묻기 | 임의 해석하지 않고 확인 질문 |
| 5 | 정책 기준을 묻기 | 근거가 없으면 확인 필요 표시 |

각 질문마다 다음을 기록한다.

- 검증 질문
- 기대 정답 또는 정답 판정 기준
- 허용 오차
- 참고 근거
- 실제 응답
- Pass/Fail 판정

### 9단계: 10턴 이상 대화 로그 수행

선정한 최종 모델로 회의록 요약 시나리오를 10턴 이상 진행한다.

반드시 포함할 상황:

- 중간에 조건 변경
- 추가 정보가 뒤늦게 제공됨

예시 흐름:

1. 회의 메모 입력
2. 요약 요청
3. Action Items만 다시 정리 요청
4. 대상 독자를 팀 내부에서 임원으로 변경
5. 뒤늦게 예산 정보 추가
6. 리스크 항목 보강 요청
7. 후속 일정만 표로 변환 요청
8. 확인 필요 사항만 추출 요청
9. 외부 공유용 표현으로 수정 요청
10. 최종본 생성 요청

문맥 유지 Pass 기준:

- 이전에 확정된 톤, 대상, 금지 사항을 유지한다.
- 조건 변경이 들어오면 변경된 부분만 반영한다.
- 원문에 없는 내용을 만들지 않는다.
- 모호한 정보는 확인 필요로 표시한다.

### 10단계: 최종 문서 정리

최종적으로 다음 항목이 빠졌는지 점검한다.

- 모델 3종 이상 비교 여부
- 평가 축 4개 이상과 점수표 포함 여부
- 최종 선정 근거 3줄 이상 포함 여부
- 타겟 사용자, 입력 데이터, 출력 규격 포함 여부
- 입력 템플릿 포함 여부
- 페르소나와 시스템 프롬프트 포함 여부
- Few-shot 예시 3개 이상 포함 여부
- v1에서 v2로 개선한 이력 포함 여부
- 환각 검증 질문 5개 이상 포함 여부
- 10턴 이상 대화 전문 포함 여부
- 조건 변경 또는 추가 정보 제공 상황 포함 여부
- 개인정보, 폭력적 콘텐츠, 선정적 콘텐츠가 포함되지 않았는지 확인

## 5. 권장 작업 순서

1. 과업을 회의록 요약으로 확정한다.
2. 테스트용 회의 메모 1개를 작성한다.
3. 3개 모델에 동일 입력을 실행한다.
4. 결과를 비교해 점수표를 작성한다.
5. 최종 모델을 선정한다.
6. 시스템 프롬프트 v1과 v2를 작성한다.
7. Few-shot 예시 3개를 작성한다.
8. 환각 검증 질문 5개를 작성한다.
9. 최종 모델로 10턴 이상 대화를 수행한다.
10. 제출 문서 3개와 원본 로그를 정리한다.
